# Ver2 Pan–Tilt 3D Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in this session. Steps use checkbox syntax for tracking.

**Goal:** Implement two-axis scans, configurable ZERO orientation, truthful 3D plots and saved datasets without connected hardware.
**Architecture:** `ScanGeometry` owns angle conversion, scan grid and mesh aggregation. `MeasurementOrchestrator` adds a separate 3D path using existing pause/abort/hold behavior, leaving the 2D pipeline compatible. GUI and DataManager consume the flat 3D point records.
**Tech Stack:** MATLAB R2025b, Arduino ESP32 / PlatformIO, existing Python VNA bridge.
**Spec:** `docs/superpowers/specs/2026-10-13-pan-tilt-3d-design.md` (approved in chat, hardware tests explicitly deferred).

## Global Constraints
- Preserve `ver1` and raw existing scan/validation data.
- No serial connections, uploads or hardware-capable test runners in this implementation session.
- Firmware numeric bounds Pan -360..360°, Tilt -180..180°; declared relative travel remains independently constrained.
- Theta 0..180°, per-axis requested span at most 360°, same manual ZERO and 30-second lease semantics.
- Missing encoder feedback aborts before the next RF sample; partial results and torque remain available.

## Review Focus
- Offset/sign changes must never cause physical ZERO or movement.
- Interrupted scans at row boundaries must not acquire an unpositioned sample.
- Invalid grids must be rejected before moving either axis.
- Duplicate poles/closure are averaged in linear amplitude without filling unmeasured rows.
- Legacy datasets and old firmware retain their limits and can run existing 2D scans.
